| 8 | AI 요청 본문 미노출 | AI 요청 JSON의 회의 원문이 사용자 응답·화면·로그에 노출되지 않는지 확인 |

## 3. 테스트 시나리오

| 번호 | 테스트 항목 | 입력 | 기대 결과 | 실제 결과 | 통과 여부 | 비고 |
| --- | --- | --- | --- | --- | --- | --- |
| T-01 | 정상 TXT 업로드 | 10MB 이하, UTF-8 회의록; 네 항목 근거와 후속 할 일 포함 | 200 응답; 네 요약 필드와 근거가 있는 투두 반환 | 사용자가 제공한 Backend 로그에서 502, 브라우저에서 응답 크기 194바이트 확인; generic provider-rejected 응답과 크기가 일치하나 원문 JSON 미확인 | 실패 | AI provider가 반환한 HTTP 상태 및 endpoint/model/request 형식 확인 필요 |
| T-02 | 빈 문서·인코딩 오류 | 빈 TXT 및 지원 인코딩으로 읽을 수 없는 TXT | 422, 원인별 안내; AI 호출 없음 | 미실행 | 미실행 | 수동 확인 |
| T-03 | 요약·투두 근거 검토 | 담당자·기한이 일부만 명시된 고정 회의록 | 네 항목 각 최대 3줄; 미확인 투두 필드 생략; 없는 후속 행동 미생성 | 미실행 | 미실행 | 원문 대조 AI 품질 확인 |
| T-04 | 결과 화면·빈 투두 | 정상 결과와 후속 할 일이 없는 결과 | 요약과 투두 분리; 빈 배열은 정상 빈 상태로 안내 | 미실행 | 미실행 | 프런트엔드 수동 확인 |
| T-05 | 파일/AI 오류와 재시도 | 비TXT, 10MB 초과, AI 설정 누락, 일시 오류, 잘못된 AI JSON | 입력별 413/415/422; 설정 503; 재시도 대상은 한 번만 재시도 후 종료 | 미실행 | 미실행 | 키·내부 오류 상세 노출 금지 |
| T-07 | CORS Origin 허용 | `http://127.0.0.1:5173` 및 `http://localhost:5173` preflight | 각 Origin에 200과 일치하는 `Access-Control-Allow-Origin` | 두 Origin 모두 200 | 통과 | 격리 서버에서 확인; 기존 8000 포트 서버 재시작 필요 |
| T-08 | Backend 오류 진단 로그 | 모의 401/404/400/429/500 및 연결 오류 확인 | 원인별 로그 분류·상태·가림 처리 endpoint 출력; API 키/요청/제공자 응답 원문 미출력 | 앱 기동·health는 통과; 오류 분기 미실행 | 미실행 | 외부 AI를 호출하지 않았고 mock provider 분류 검증 필요 |
| T-09 | AI 요청 본문 미노출 | 유효 TXT 분석 성공 또는 AI 오류 | 응답과 화면에는 요약·투두 결과만 표시하고 원문 프롬프트, API 키, 제공자 응답 본문은 포함하지 않음 | 미실행 | 미실행 | 구현 반영 후 응답·화면·로그를 확인해야 함 |

## 4. API 테스트

| Method | Endpoint | 입력 | 기대 상태 코드 | 실제 상태 코드 | 통과 여부 |
| --- | --- | --- | --- | --- | --- |
| GET | `/api/health` | 없음 | 200 및 `{"status":"ok"}` | 200, `{"status":"ok"}` | 통과 |
| POST | `/api/v1/analyses` | 사용자가 업로드한 TXT `file` | AI 설정 연결 시 200 | 사용자 화면 Network 로그에서 502; 응답 본문 미확인 | 실패 |
| POST | `/api/v1/analyses` | TXT가 아닌 파일 | 415 | 미실행 | 미실행 |
| POST | `/api/v1/analyses` | 빈 파일 | 422 | 미실행 | 미실행 |
| POST | `/api/v1/analyses` | 10MB 초과 TXT | 413 | 미실행 | 미실행 |
| POST | `/api/v1/analyses` | AI 설정이 비어 있는 유효 TXT | 503 | 미실행 | 미실행 |
| OPTIONS | `/api/v1/analyses` | `Origin: http://127.0.0.1:5173`, POST preflight | 200 및 일치하는 `Access-Control-Allow-Origin` | 200, 허용 헤더 확인 | 통과 |
| OPTIONS | `/api/v1/analyses` | `Origin: http://localhost:5173`, POST preflight | 200 및 일치하는 `Access-Control-Allow-Origin` | 200, 허용 헤더 확인 | 통과 |

후속 조치 (2026-11-15): 사용 중 확인된 AI JSON 파싱 및 요약 형식 검증 실패에 대응해 Chat Completions 요청에 단계별 `json_schema` 구조화 출력을 적용하고, 응답값을 포함하지 않는 유효성 검증 실패 로그를 추가했다. 수정 후 로컬 재분석은 아직 실행하지 않았으므로 성공 여부는 확인 필요.

## 구현 단계 판정

- 판정: **확인 필요**
- 근거: 가상환경 의존성 설치와 두 개발 Origin의 CORS preflight 200을 별도 서버에서 확인했습니다. 사용자가 제공한 분석 요청은 502이며 상세 응답 본문이 없어 AI 공급자 오류와 Agent 출력 검증 오류 중 원인을 확정하지 못했습니다. AI 결과 품질도 검증하지 않았습니다.
- 남은 항목: 기존 8000 포트 Backend를 새 설정으로 재시작한 뒤 브라우저 요청을 확인합니다. CORS가 해결된 뒤에도 502가 남으면 Network → Response의 `error.message`, `error.action`을 확인하고 실제 고정 샘플로 AI 품질을 별도 검토합니다.
