# MVP 계획서

작성: Planner / 2026-11-15

## 1. MVP 목표

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | after meeting (미팅 후속 업무 자동처리 Agent) |
| 기준 자료 | `docs/requirements.md`, `docs/function-breakdown.md`, 이 계획서 |
| 현재 기술 구성 | Backend: FastAPI / Frontend: React + Vite / AI: OpenAI Chat Completions API, `gpt-6-luna`, `reasoning_effort=high`; API 키는 로컬 환경 변수 |
| MVP 한 줄 설명 | 사용자가 STT로 이미 추출된 TXT 회의 텍스트를 업로드하면, AI가 정해진 형식으로 요약하고 요약에서 후속 할 일을 정리해 화면에 보여주는 서비스 |
| 검증할 핵심 가치 | 회의 텍스트를 직접 다시 읽고 정리하는 시간을 줄이면서, 회의 안건·문제·해결방안·결론과 후속 할 일을 한 번에 확인할 수 있는지 검증한다. |
| 시연 방식 | 10MB 이하의 샘플 TXT 파일을 업로드해 입력 검증, 네 항목 요약, 요약 기반 투두리스트, 오류 안내까지 확인한다. |

## 2. MVP 사용자 흐름

| 순서 | 사용자 또는 시스템 | 동작 |
| --- | --- | --- |
| 1 | 사용자 | 이미 STT로 추출된 회의 내용이 들어 있는 TXT 파일을 선택해 업로드한다. 직접 텍스트 입력은 제공하지 않는다. |
| 2 | 서비스 | TXT 형식, 10MB 이하 크기, 파일 읽기 가능 여부와 빈 내용 여부를 검사한다. 최소 글자 수 기준은 두지 않는다. |
| 3 | AI | 유효한 회의 텍스트를 회의 안건·문제점·해결방안·결론으로 요약한다. 각 항목은 최대 3줄로 제한한다. |
| 4 | 서비스 | 요약의 필수 항목 및 줄 수를 확인한 뒤, 통과한 요약을 다음 AI 처리 단계에 전달한다. |
| 5 | AI | 요약에 명시된 후속 행동을 투두리스트로 정리한다. 할 일, 담당자, 기한, 우선순위를 출력하고 근거가 없는 필드는 생략한다. |
| 6 | 서비스 | 요약과 투두리스트를 구분해 화면에 표시한다. 할 일이 없으면 빈 목록 상태를 구분해 안내한다. |
| 7 | 사용자 | 결과를 원문과 대조해 확인하고 업무에 활용할 내용을 검토한다. |
| 예외 | 서비스 | 파일 또는 AI 처리에 실패하면 실패 단계와 조치 권장안을 안내한다. 일시 오류는 최대 1회 재시도하고, 다시 실패하면 오류 상태로 종료한다. |

## 3. MVP에 포함할 기능

| 번호 | 기능 | 설명 | 포함 이유 |
| --- | --- | --- | --- |
| 1 | TXT 파일 업로드 및 입력 검증 (F-01~F-04) | TXT 파일만 받고, 최대 10MB·읽기 가능 여부·빈 내용 여부를 확인한다. | 사용자가 가진 STT 텍스트를 서비스 처리 흐름에 넣는 시작점이다. |
| 2 | 검증된 텍스트 전달 (F-05) | 읽은 회의 텍스트를 분석 단계에 전달한다. | 업로드와 AI 분석을 연결해야 사용자 흐름이 완성된다. |
| 3 | 기본 입력 오류 안내 (F-06) | 형식 불일치, 크기 초과, 읽기 실패, 빈 파일을 구분해 안내한다. | 잘못된 입력이 정상 결과로 이어지는 것을 막는다. |
| 4 | AI 회의 요약 및 형식 확인 (F-07~F-08) | 회의 안건·문제점·해결방안·결론을 각 최대 3줄로 작성하고 필수 항목과 줄 수를 검사한다. | 프로젝트의 핵심 AI 기능이며, 요구된 출력 형식을 보장하는 최소 검증이 필요하다. |
| 5 | 요약 기반 투두리스트 생성 및 필드 확인 (F-09~F-10) | 요약에서 명시된 후속 행동을 뽑아 할 일·담당자·기한·우선순위를 구성한다. 확인되지 않은 필드는 생략한다. | 회의 후속 업무 자동 정리라는 핵심 가치를 제공한다. |
| 6 | 결과 화면 표시 (F-11) | 네 항목 요약과 투두리스트를 구분해 보여준다. | 사용자가 결과를 검토할 수 있어야 MVP의 입력부터 출력까지 검증할 수 있다. |
| 7 | 기본 AI 오류 안내 (F-12) | 실패 단계와 사용자가 취할 조치를 표시하고, 일시 오류는 최대 1회만 재시도한다. | AI 호출 실패나 형식 오류가 발생해도 상태와 복구 방법을 알 수 있어야 한다. |
| 8 | 실행·사용 안내 문서 | macOS 환경 설정·실행 방법, 서버 키 설정 위치, 샘플 입력과 확인 방법을 README에 기록한다. | 다른 팀원이 MVP를 실행하고 재현할 수 있어야 한다. |

## 4. MVP에서 제외할 기능

| 번호 | 기능 | 제외 이유 | 후순위 처리 방향 |
| --- | --- | --- | --- |
| 1 | 음성 녹음 및 STT 변환 | 프로젝트 범위는 이미 추출된 TXT를 분석하는 것이다. | 현재 계획하지 않는다. |
| 2 | 사용자의 텍스트 직접 입력 | 요구사항은 TXT 업로드만 지원한다고 정했다. | 입력 방식 변경 요청이 있을 때 재검토한다. |
| 3 | 회의 안건별 소분류 | 요구사항에서 MVP 이후 기능으로 지정됐다. | 요약 결과 기준과 분류 항목을 정한 뒤 별도 기능으로 설계한다. |
| 4 | 명함 정보 추출 및 후속 메일 초안 작성 | MVP 핵심인 요약·투두리스트 검증에 필수적이지 않고 별도 입력·출력 계약이 필요하다. | MVP 이후 기능으로 유지한다. |
| 5 | 결과 및 입력 TXT 다운로드, 완성 화면 PDF 다운로드 | 화면에서 결과를 확인하는 것만으로 핵심 흐름을 검증할 수 있어 1일 MVP 범위에서 제외한다. | 결과 화면이 안정화된 뒤 내보내기 기능으로 설계한다. |
| 6 | 로그인, 분석 이력, 데이터베이스 저장 | 단일 입력으로 핵심 결과를 생성하는 데 필수적이지 않다. 저장·개인정보 정책도 추가 결정이 필요하다. | 저장 요구와 보관 정책을 확정한 뒤 검토한다. |
| 7 | AI가 생성한 결과의 수정·공유 기능 | 결과 자동 생성의 핵심 가치를 검증하는 데 필수적이지 않다. | 사용자 피드백을 받은 뒤 우선순위를 정한다. |

## 5. 구현 순서

| 순서 | 작업 | 결과물 | 확인 방법 |
| --- | --- | --- | --- |
| 1 | OpenAI API 키·별도 API 결제 설정 | OpenAI API 연결과 데이터 취급 기준 | 모델·endpoint는 정했다. 키는 Backend 로컬 환경 변수에만 설정하며 ChatGPT 구독과 API 결제는 별도로 확인한다. |
| 2 | TXT 업로드와 입력 검증 구현 | 업로드 화면 및 검증 처리 | 정상 TXT, 10MB 초과, TXT 외 형식, 빈 파일, 읽기 실패 입력으로 분기 확인 |
| 3 | 요약 생성 및 형식 검증 연결 | 네 항목 요약 처리 | 네 항목 존재, 항목별 최대 3줄, 원문에 없는 사실 생성 여부를 검토 |
| 4 | 요약 기반 투두리스트 생성 및 검증 연결 | 투두 항목 처리 | 할 일·담당자·기한·우선순위 연결과 근거 없는 항목·필드 생략 여부를 검토 |
| 5 | 결과 및 오류 화면 연결 | 결과 화면과 기본 오류 안내 | 성공·빈 투두·업로드 실패·AI 실패에서 올바른 상태와 안내가 표시되는지 확인 |
| 6 | 수동 시연 점검 및 README 작성 | 재현 가능한 MVP 안내 | 샘플 TXT와 실행 방법으로 팀원이 처음부터 결과까지 확인한다. |

애플리케이션은 FastAPI와 React/Vite, OpenAI Chat Completions API의 `gpt-6-luna`를 사용하며 `reasoning_effort=high`를 기본 설정한다. 실제 API 키와 API 결제 설정은 각 개발 환경에서 별도로 준비한다.

## 6. 완료 기준

| 기준 | 확인 방법 | 통과 여부 |
| --- | --- | --- |
| 사용자가 입력을 넣을 수 있다 | TXT 파일을 업로드하고 파일 형식·크기·읽기·빈 내용 검증 결과를 확인한다. 10MB 이하는 다음 단계로 진행하고 초과 파일은 거부한다. | 계획 기준: 미실행 |
| AI 처리 결과를 확인할 수 있다 | 결과에 회의 안건·문제점·해결방안·결론이 각각 표시되고 각 항목이 최대 3줄인지 확인한다. | 계획 기준: 미실행 |
| 투두리스트가 요약에서 생성된다 | 요약에 명시된 후속 행동만 할 일로 출력하고, 확인 가능한 담당자·기한·우선순위를 연결한다. 근거가 없는 필드는 생략한다. | 계획 기준: 미실행 |
| 결과 영역이 구분된다 | 요약과 투두리스트가 별도 영역으로 표시되며 할 일이 없을 때 오류와 구분되는 빈 상태를 보여준다. | 계획 기준: 미실행 |
| 오류 상황을 확인할 수 있다 | 업로드·읽기 오류와 AI 오류가 성공 결과와 구분되고, 단계에 맞는 조치 안내가 표시된다. AI 일시 오류는 최대 1회 재시도 후 지속 실패 상태를 보여준다. | 계획 기준: 미실행 |
| 원문·요청 본문이 사용자 응답에 노출되지 않는다 | 성공/오류 응답과 화면에 회의 원문 및 AI 요청 본문이 없고, 서버 로그에도 기록되지 않는지 확인한다. | 계획 기준: 미실행 |
| README를 보고 실행할 수 있다 | README의 환경 설정·실행·샘플 입력 절차를 다른 팀원이 따라 결과를 확인한다. | 계획 기준: 미실행 |

## 7. 테스트 또는 수동 확인 방법

| 항목 | 내용 |
| --- | --- |
| 실행 명령 | macOS 명령은 README에 기록한다. Backend는 가상환경에서 Uvicorn, Frontend는 Vite 개발 서버로 실행한다. |
| 입력 예시 | 10MB 이하의 샘플 TXT. 회의 안건, 논의된 문제, 해결방안, 결론, 담당자와 기한이 포함된 후속 행동을 포함한다. 별도 샘플 파일은 아직 준비되지 않았다. |
| 기대 결과 | 네 개 요약 영역이 각각 최대 3줄로 표시되고, 요약에서 확인되는 후속 행동이 할 일·담당자·기한·우선순위와 함께 표시된다. 원문/요약에 없는 필드는 생략된다. |
| 오류 상황 확인 | TXT가 아닌 파일, 10MB 초과 파일, 빈 파일, 읽을 수 없는 TXT, 외부 AI 호출 실패, 형식이 잘못된 AI 응답을 입력해 오류 안내와 중단 흐름을 확인한다. |

## 추적과 AI 결과 품질

| 포함 F-ID / R-ID | 의존성·구현 순서 | T-ID | 고정 입력 | 필수 사실·근거 | 금지 오류 | 판정 방법 |
| --- | --- | --- | --- | --- | --- | --- |
| F-01~F-06 / R-01, R-05 | 파일 업로드 → 검증 → 읽기 → 오류 분기 → 분석 단계 전달 | T-01, T-05 | 정상 TXT, 빈 TXT, 10MB 초과, TXT가 아닌 파일, 읽기 실패 파일 | 유효 TXT의 본문이 분석 단계까지 전달되고, 오류 입력은 중단됨 | 잘못된 입력을 성공 분석 처리하거나 오류 상태를 숨김 | 각 입력 결과와 화면 안내를 수동 확인 |
| F-07~F-08 / R-02 | 검증 텍스트 → 요약 → 형식 확인 | T-02 | 회의 안건·문제·해결·결론을 포함한 고정 TXT, 각 항목의 근거가 없는 변형 TXT | 네 항목의 핵심 사실이 원문에 근거하고 각 항목 최대 3줄 | 원문에 없는 인물·결정·해결방안 생성, 핵심 사실 왜곡, 항목 누락, 줄 수 초과 | 원문과 결과를 항목별로 대조. 실제 AI 품질 평가는 구현 후 수동 검토 |
| F-09~F-10 / R-03 | 검증된 요약 → 후속 행동 추출 → 필드 확인 | T-03 | 요약에 할 일·담당자·기한·우선순위가 있는 입력과 각 필드 일부가 없는 입력 | 할 일이 요약에 근거하고 존재하는 정보를 해당 필드에 표시 | 없는 할 일·담당자·기한·우선순위 발명, 근거 없는 날짜·담당자 생성 | 요약과 투두를 대조하고 누락 필드 생략을 확인 |
| F-11 / R-04 | 검증된 요약과 투두 → 결과 화면 | T-04 | 정상 결과와 투두가 없는 결과 | 요약과 투두가 분리 표시되고 빈 투두 상태가 구분됨 | 요약·투두 혼합, 빈 목록을 오류나 완료 항목으로 오인 | 화면에서 두 영역과 빈 상태를 확인 |
| F-12 / R-05 | 업로드·요약·투두 오류 → 조치 안내 | T-05 | 파일 검증 오류, AI 호출 실패, 잘못된 AI 출력, 재시도 후 지속 실패 | 실패 단계와 사용자 조치가 표시되고 마지막에는 명확히 종료됨 | 실패를 성공으로 표시, 비밀 키·내부 로그 노출, 무제한 재시도 | 오류 종류별 상태·안내와 재시도 1회 제한을 수동 확인 |
| F-05/F-12 / R-01, R-05 | AI 요청 → API 응답·로그·화면 | T-09 | 성공 응답과 AI 호출 오류 | 응답에는 결과 또는 안전한 오류만 있고 원문 프롬프트가 없음 | 회의 원문·API 키·제공자 응답 본문이 브라우저나 로그에 노출 | 응답·화면을 수동 점검; AI 본문은 비교용 로그로 저장하지 않음 |

위 T-ID는 요구사항 정의서에 있는 시나리오 ID를 재사용한다. 고정 샘플과 실행 환경이 준비되지 않아 계획 단계에서는 테스트를 실행하지 않았다.

기능 통과와 AI 품질 평가는 별도로 판정한다. 형식(항목 존재·줄 수) 검사는 기계적으로 확인하고, 요약의 사실 보존과 투두의 근거 여부는 고정 TXT를 원문과 대조해 사람이 확인한다. 승인된 품질 점수나 정확도 임계값은 정해지지 않았으므로 임의 수치를 두지 않는다.

## 가정 사항

| 가정 | 근거 | 틀릴 때 영향 |
| --- | --- | --- |
| 업로드 크기 10MB 이하를 허용하고 초과는 거부한다. | 사용자가 확정한 기능 분해 기준 | 요구사항 정의서에는 이전의 미정 표시가 남아 있을 수 있으므로 문서 정합성은 후속 정리 대상이다. |
| 투두 생성은 원문 전체가 아니라 요약 결과를 입력으로 사용한다. | 사용자 요청의 “요약 기능을 통한 투두리스트 생성” | 요약에 후속 행동이 충분히 보존되지 않으면 할 일이 누락될 수 있다. |
| 담당자·기한·우선순위 중 요약에서 확인되지 않는 값은 생략한다. | 최신 기능 분해 문서의 필드 처리 기준 | 사용자가 빈 값 표시를 원하면 결과 형식과 검증 규칙을 바꿔야 한다. |
| 결과는 우선 화면에서 확인하며 다운로드 기능은 MVP에서 제외한다. | 핵심 가치 검증에 화면 출력이 충분하고 하루 개발 범위가 제한됨 | TXT/PDF 저장이 필수 시연 조건이면 해당 범위를 재선정해야 한다. |
| AI 분석 오류는 일시 오류에 한해 1회 재시도하고, 다시 실패하면 안내 후 중단한다. | 지속 실패 시 오류 문구와 처리 방식을 정하라는 요구 | 팀이 재시도 횟수나 복구 정책을 다르게 정하면 오류 흐름을 수정해야 한다. |

## 확인 필요 사항과 단계 판정

| 미정 사항 | 담당·확인 방법·시점 | 영향·진행 가능 범위 |
| --- | --- | --- |
| OpenAI API 키·결제 준비 | 각 개발자/프로젝트 소유자, API 플랫폼에서 키 발급 및 결제 상태 확인 | 실제 분석 요청과 비용에 영향; 키는 저장소에 넣지 않음 |
| 회의 원문 외부 전송·보관 조건 | 팀/강사, OpenAI 데이터 정책 및 사용자 고지 확인 | 회의 내용 외부 전송에 관한 동의·보안 기준에 영향 |
| AI 결과에 필수 요약 항목의 근거가 없을 때 표시 | 팀이 고정 샘플 결과를 검토해 결정 | 네 항목을 모두 표시할지, 미기재 상태를 어떻게 표현할지 영향 |
| 투두 우선순위의 값과 분류 기준 | 팀에서 샘플 회의록으로 합의 | AI 결과 일관성과 수용 기준에 영향 |
| AI 오류 권장안의 제공 방식 | 팀에서 실패 시나리오를 정해 결정 | AI 서비스 장애 시 AI를 다시 호출할지, 고정 안내를 사용할지 영향 |
| 결과 TXT/PDF 다운로드의 MVP 포함 여부 | 제출·시연 조건과 남은 개발 시간을 기준으로 팀에서 결정 | 제외하면 화면 확인만 제공하고, 필요 시 구현 범위·일정 조정 필요 |
| 개인정보·원문 처리 및 저장 정책 | 팀과 강사에게 확인, 외부 AI 연동 전 | 외부 전송 동의·저장 여부와 보안 기준에 영향 |

- 설계 판정: 통과 — MVP 목표, 사용자 흐름, 포함/제외 범위, 완료 기준과 추적 기준을 정리했다.
- 구현 판정: 확인 필요 — 구현은 연결했으나 이번 변경에서 앱 실행, 브라우저 확인, 분석 API 및 AI 품질 검증은 수행하지 않았다.
- 남은 결정: API 결제·키 발급, 회의 원문 외부 전송 정책, 투두 우선순위 값, 요약 항목 근거가 없을 때의 표시 기준을 팀에서 확정한다.
- 다음 단계: [프로젝트 구조 설계](project-structure.md)와 README를 기준으로 로컬 실행 및 미실행 시나리오를 확인한 후, 실제 AI 설정으로 고정 샘플 품질을 검토한다.
