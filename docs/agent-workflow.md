# 회의 분석 Workflow

작성: Builder / 2026-11-15

## 1. 목표와 범위

TXT 회의 내용을 요약하고, 검증된 요약에서 근거가 확인되는 후속 할 일만 추출하는 고정 순차 흐름입니다. 검색·도구 선택·상태 영속화가 없으므로 MVP에서는 별도 LangChain/LangGraph 그래프 없이 `AnalysisWorkflow`가 순서를 관리합니다.

## 2. 단계와 계약

| 단계 | 입력 | 처리 | 출력 | 다음 단계 / 실패 |
| --- | --- | --- | --- | --- |
| 문서 입력 (F-01~F-05) | 업로드된 TXT | 형식·10MB 크기·디코딩·빈 내용 검증 | `meeting_text` 문자열 | 요약으로 전달; 입력 오류는 F-06 안내로 종료 |
| 요약 생성 (F-07) | `meeting_text` | 회의 안건·문제점·해결방안·결론을 한국어로 생성; 항목별 최대 3줄 | 네 필드 요약 객체 | 형식 검증 |
| 요약 검증 (F-08) | 요약 객체 | 필수 필드 문자열인지, 각 필드 최대 3줄인지 확인 | 검증된 요약 | 통과 시 투두 생성; 오류는 최대 1회 재시도 후 F-12 |
| 투두 생성 (F-09) | 검증된 요약 | 명시된 후속 행동을 추출; 근거 없는 담당자·기한·우선순위는 발명하지 않음 | `todos[]` | 투두 필드 검증 |
| 투두 검증 (F-10) | 투두 배열 | 각 항목의 `task` 확인; 선택 필드는 근거가 있는 경우만 허용 | 검증된 투두 목록 | 통과 시 결과 표시; 형식 오류는 최대 1회 재시도 후 F-12 |
| 결과 표시 (F-11) | 검증된 요약·투두 | 두 영역을 분리하고 빈 투두 배열을 정상 상태로 표시 | 결과 화면 | 사용자가 원문과 대조 |
| 오류 안내 (F-06/F-12) | 실패 단계·내부 오류 분류 | 사용자용 메시지와 복구 행동 제공. 키·원문·stack trace는 숨김 | 오류 화면 | 재시도 종료 후 실패 상태 |

## 3. 흐름

```text
TXT 업로드
  → 형식·크기·읽기·내용 검증
  → 회의 텍스트 요약
  → 요약 필드·줄 수 검증 ── 실패: 1회 재시도 후 오류 종료
  → 검증된 요약으로 투두 생성
  → 투두 항목 검증 ─────── 실패: 1회 재시도 후 오류 종료
  → 요약·투두를 분리해 표시
```

각 AI 단계는 최대 두 번 요청합니다(첫 요청과 재시도 한 번). 입력 파일 오류와 설정 오류는 자동 재시도하지 않습니다. 재시도 사이 대기 시간은 구현하지 않습니다.

## 4. 입력 문서와 프롬프트 경계

- 업로드된 문서와 요약은 분석 데이터로 취급합니다.
- 문서 안의 지시문이나 프롬프트 문구는 실행 지시로 따르지 않고 회의 내용으로만 분석합니다.
- 회의 원문을 성공 응답이나 애플리케이션 로그에 포함하지 않습니다. 외부 AI 전송은 분석에 필요한 처리이며, 제공자를 선택하기 전에 데이터 취급 조건을 확인해야 합니다.

## 5. AI 품질 검토 기준

| 대상 | 통과 기준 | 금지 오류 | 판정 |
| --- | --- | --- | --- |
| 요약 | 네 필드가 있고 각 필드는 최대 3줄; 내용은 회의 원문에 근거 | 인물·결정·문제·해결방안·결론을 지어내거나 핵심 사실을 바꿈 | 형식은 코드 검증, 사실성은 고정 회의 TXT와 사람이 대조 |
| 투두 | 할 일이 요약에 근거하고, 확인되는 필드만 표시; 할 일이 없으면 빈 배열 | 근거 없는 할 일·담당자·기한·우선순위를 만듦 | 투두와 요약/원문을 사람이 대조 |

품질 점수나 정확도 임계값은 정해지지 않았습니다. 실제 AI 품질 평가는 외부 제공자 설정과 고정 샘플을 정한 후 별도로 수행합니다.

## 확인과 판정

- 판정: 확인 필요
- 근거: 정상 흐름·검증 분기·재시도 한도·오류 종료를 정의했습니다. 제공자 장애 시 지원되는 구조화 출력과 외부 데이터 처리 조건은 미정입니다.
- 실행 검증: 해당 없음. Workflow 설계 문서이며 AI 호출을 수행하지 않았습니다.
