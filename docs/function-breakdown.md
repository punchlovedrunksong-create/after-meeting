## 3. API 기능 목록

| 기능              | Endpoint 후보               | 설명                                                                             | 우선순위 |
| --------------- | ------------------------- | ------------------------------------------------------------------------------ | ---- |
| TXT 문서 업로드 및 읽기 | `POST /documents` (후보)    | TXT 파일을 받아 형식·크기·내용을 검증하고, 읽은 텍스트를 분석 흐름에 전달한다. 경로와 요청·응답 형식은 기술 구조 결정 후 확정한다. | 높음   |
| AI 분석 요청        | `POST /analyses` (후보)     | 검증된 TXT 내용을 받아 요약·투두리스트 생성 흐름을 시작하고 결과 또는 진행 상태를 반환한다. 동기/비동기 방식과 응답 계약은 미정이다. | 높음   |
| 분석 결과 조회        | `GET /analyses/{id}` (후보) | 비동기 처리로 결정되는 경우 분석 상태와 완료 결과를 제공한다. 분석 ID와 저장 방식 채택 여부는 확인 필요다.                | 중간   |

`POST /documents`와 `POST /analyses`, `GET /analyses/{id}`는 설명을 위한 후보 경로이며 확정 API 명세가 아니다. 인증·결과 저장 방식과 동기/비동기 처리 구조는 기술 구조 결정 후 확정한다.

## 4. AI Agent 기능 목록

| Agent 기능                 | 입력                            | 처리                                                                                     | 출력                         | 우선순위  |
| ------------------------ | ----------------------------- | -------------------------------------------------------------------------------------- | -------------------------- | ----- |
| 입력 단계에서 직접 수행하는 AI 기능 없음 | 해당 없음                         | 파일 형식·크기·빈 내용 검사는 일반 입력 처리로 수행한다. 유효한 텍스트를 후속 분석 Agent에 넘기는 지점까지만 설계한다.                | 검증된 텍스트 전달                 | 해당 없음 |
| 회의 내용 요약                 | 검증된 TXT 텍스트                   | 회의 안건, 회의 내용의 문제점, 해결방안, 결론을 구분해 요약하고 항목별 최대 3줄로 제한한다. 원문에 없는 내용은 만들어내지 않는다.           | 네 항목으로 구성된 요약              | 높음    |
| 요약 기반 투두리스트 생성           | 형식 검증을 통과한 요약                 | 요약에 명시된 후속 행동을 할 일 단위로 정리하고, 근거가 없는 할 일은 추가하지 않는다. 담당자·기한·우선순위는 근거가 없을 때 임의 생성하지 않는다.  | 할 일, 담당자, 기한, 우선순위가 포함된 목록 | 높음    |
| AI 출력 형식 확인              | Summary Agent 및 Todo Agent 결과 | 필수 필드·구조를 확인하고 결과 표시 가능한 상태인지 판단한다. 재시도 정책 및 한도는 미정이다.                                 | 검증 통과 결과 또는 실패 상태          | 높음    |

이 문서에 입력 단계에 이어 AI 요약과 요약 기반 투두리스트 기능을 추가 설계한다. 요구사항의 출력 형식은 회의 안건·회의 내용의 문제점·해결방안·결론이며 각 항목은 최대 3줄이다. 투두리스트에는 할 일·담당자·기한·우선순위를 포함한다.

## 기능별 상세 계약

### F-01 — TXT 파일 선택 및 업로드 요청

* **선행 기능:** 없음

* **후행 기능:** F-02

* **입력 필드·타입·필수 여부:** 파일 객체(필수), 파일명(필수), 파일 크기(필수로 확인 가능해야 함). UI/API의 구체 타입은 기술 구조 결정 후 확정한다.

* **처리:** 사용자가 TXT 파일을 선택하고 업로드를 요청한다. 직접 텍스트 입력은 받지 않는다.

* **출력 필드·타입:** 선택 파일 정보와 업로드 요청 상태. 구체 응답 형식은 미정이다.

* **실패 조건:** 파일 미선택, 업로드 요청 실패.

* **사용자 안내:** 파일을 선택하도록 안내하거나 업로드 실패 상태를 표시한다. 실제 문구는 UI 설계에서 확정한다.

* **후속 단계 진행·중단:** 파일이 선택되어 업로드되면 F-02로 진행한다. 선택 또는 업로드가 실패하면 입력 검증을 시작하지 않는다.

* **검증 입력·기대값:** 정상 TXT를 선택하면 해당 파일이 업로드 요청에 포함된다. 파일을 선택하지 않으면 업로드가 진행되지 않고 선택 안내가 표시된다.

### F-02 — 파일 형식·크기 검증

* **선행 기능:** F-01

* **후행 기능:** F-03

* **입력 필드·타입·필수 여부:** 파일명·파일 형식 정보 및 파일 크기(필수). 확장자·MIME 정보 중 어떤 기준을 쓸지는 구현 구조에서 정한다.

* **처리:** 요구사항에 맞는 TXT 파일인지 확인한다. 최대 크기 기준은 미정이므로 구현 전에 정해야 한다.

* **출력 필드·타입:** 검증 통과/실패 상태와 실패 이유.

* **실패 조건:** TXT가 아닌 형식, 합의된 크기 제한 초과, 형식 정보 확인 실패.

* **사용자 안내:** TXT 파일만 지원함을 알리고, 크기 초과 시 허용 크기를 안내한다. 허용 크기는 확인 후 표시한다.

* **후속 단계 진행·중단:** 검증 통과 시 F-03으로 진행한다. 실패 시 읽기와 Agent 전달을 중단한다.

* **검증 입력·기대값:** TXT는 다음 단계로 전달된다. TXT가 아닌 입력은 거부된다. 크기 경계값은 제한을 결정한 뒤 검증한다.

### F-03 — TXT 텍스트 읽기

* **선행 기능:** F-02

* **후행 기능:** F-04

* **입력 필드·타입·필수 여부:** 업로드된 TXT 파일 데이터(필수).

* **처리:** 파일의 텍스트 내용을 읽는다. 지원 문자 인코딩과 인코딩 오류 복구 방식은 확인이 필요하다.

* **출력 필드·타입:** 읽은 회의 텍스트(문자열) 또는 읽기 오류 상태.

* **실패 조건:** 파일 데이터 손상, 지원하지 않는 인코딩, 읽기 권한·처리 오류.

* **사용자 안내:** 파일 내용을 읽을 수 없음을 알리고, TXT 파일을 다시 확인해 업로드하도록 안내한다. 지원 인코딩 목록은 확정 후 안내한다.

* **후속 단계 진행·중단:** 읽기에 성공하면 F-04로 진행한다. 실패하면 분석 단계로 전달하지 않는다.

* **검증 입력·기대값:** 읽을 수 있는 TXT는 파일 본문이 문자열로 반환된다. 읽을 수 없는 입력은 오류 상태로 종료되고 분석 요청이 발생하지 않는다.

### F-04 — 내용 유효성 확인

* **선행 기능:** F-03

* **후행 기능:** F-05

* **입력 필드·타입·필수 여부:** 읽은 회의 텍스트(문자열, 필수).

* **처리:** 내용이 비어 있거나 공백만 있는지 확인한다. 최소 글자 수 또는 최소 정보량 기준은 현재 정해지지 않았다.

* **출력 필드·타입:** 전달 가능한 텍스트 또는 내용 오류 상태.

* **실패 조건:** 빈 파일, 공백만 있는 내용, 내부 처리 오류.

* **사용자 안내:** 회의 텍스트가 없음을 알리고 내용이 포함된 파일을 업로드하도록 안내한다.

* **후속 단계 진행·중단:** 내용이 있으면 F-05로 진행한다. 빈 내용이면 분석을 중단한다.

* **검증 입력·기대값:** 일반 텍스트가 포함된 파일은 통과한다. 빈 파일 및 공백만 있는 파일은 분석 단계로 전달되지 않는다.

### F-05 — 분석 단계로 텍스트 전달

* **선행 기능:** F-04

* **후행 기능:** F-07 회의 텍스트 요약

* **입력 필드·타입·필수 여부:** 검증된 회의 텍스트(문자열, 필수).

* **처리:** 검증된 원문 텍스트를 F-07 요약 Agent에 전달한다. 요약·투두리스트 생성은 후속 기능 F-07~F-10에서 수행하며, 데이터 저장과 외부 모델 선택은 이 기능에서 결정하지 않는다.

* **출력 필드·타입:** 전달 상태 및 후속 처리에 사용할 텍스트. 구체 인터페이스는 Agent/API 구조 결정 후 확정한다.

* **실패 조건:** 후속 분석 흐름에 전달할 수 없거나 연계 요청이 실패함.

* **사용자 안내:** 입력 전달이 실패했음을 알린다. 재시도 방식과 후속 오류 처리 책임은 연계 설계에서 확정한다.

* **후속 단계 진행·중단:** 성공하면 별도 분석 기능으로 넘긴다. 실패하면 분석 결과를 성공으로 표시하지 않는다.

* **검증 입력·기대값:** 검증된 텍스트가 후속 분석 단계 입력으로 전달되고, 입력 단계에서 텍스트 내용이 임의 변경·요약되지 않는다.

### F-06 — 입력 오류 상태 및 안내

* **선행 기능:** F-01\~F-05 중 오류가 발생한 단계

* **후행 기능:** 사용자가 입력을 수정한 후 재시도하거나 작업을 종료

* **입력 필드·타입·필수 여부:** 오류 단계와 오류 상태(필수), 구체 오류 코드·문구는 구현 전 정의 필요.

* **처리:** 형식, 크기, 읽기, 빈 내용, 업로드 실패를 성공 처리와 구분하고 사용자에게 안내한다.

* **출력 필드·타입:** 오류 상태와 사용자 안내 메시지.

* **실패 조건:** 오류 상태가 표시되지 않거나 실패 입력이 정상 분석으로 전달됨.

* **사용자 안내:** 문제 종류를 알리고 사용자가 취할 수 있는 조치를 설명한다. AI 분석 오류에 대한 권장안은 F-12에서 다룬다.

* **후속 단계 진행·중단:** 오류가 난 입력은 분석 단계로 진행하지 않는다. 재시도 지원 방식은 확인 필요다.

* **검증 입력·기대값:** 각 입력 오류에서 오류 상태가 표시되고, 해당 실패 입력에 대해 요약·투두리스트 결과가 성공으로 표시되지 않는다.

### F-07 — 회의 텍스트 요약

* **선행 기능:** F-05 검증된 텍스트 전달

* **후행 기능:** F-08 요약 형식 검증, 이후 F-09 투두리스트 생성

* **입력 필드·타입·필수 여부:** `meeting_text` (문자열, 필수). 업로드 원문에서 읽힌 전체 텍스트.

* **처리:** AI Agent가 입력을 분석해 `meeting_agenda`, `issues`, `solutions`, `conclusion` 네 항목으로 정리한다. 각 항목은 논리적 줄바꿈 기준 최대 3줄로 작성한다. 입력 텍스트에 근거가 없는 사실·문제점·해결방안·결론을 단정해 만들어내지 않는다.

* **출력 필드·타입:** `summary.meeting_agenda`, `summary.issues`, `summary.solutions`, `summary.conclusion` (각 문자열, 필수). 실제 응답 직렬화 형식은 구현 구조에서 결정한다.

* **실패 조건:** AI 서비스 오류·시간 초과, 입력이 요약에 부족함, 필수 항목 누락, 항목별 3줄 초과.

* **사용자 안내:** 요약 생성 실패 여부를 알리고 재시도 또는 입력 확인 안내를 제공한다. 입력 부족 항목을 어떻게 표시할지(예: ‘원문에서 확인되지 않음’)는 팀 확인이 필요하다.

* **후속 단계 진행·중단:** 형식 검증을 통과하면 F-09로 전달한다. 검증 실패 결과는 정상 요약으로 표시하지 않는다. 재생성 횟수와 종료 조건은 미정이다.

* **검증 입력·기대값:** 회의 안건, 논의된 문제, 해결방안, 결론이 각각 포함된 TXT에서 네 항목이 출력되고 각각 최대 3줄이다. 항목에 근거가 없는 입력은 내용을 꾸며내지 않는 것이 기대값이며, 표시 문구는 확정이 필요하다.

### F-08 — 요약 형식 검증

* **선행 기능:** F-07

* **후행 기능:** 성공 시 F-09, 실패 시 F-12

* **입력 필드·타입·필수 여부:** F-07의 요약 객체(필수).

* **처리:** 네 항목이 모두 존재하는지, 각 항목이 최대 3 논리 줄인지, 요약 결과가 비어 있지 않은지 확인한다. 사실성·품질의 자동 평가 기준은 아직 정의되지 않았다.

* **출력 필드·타입:** 검증된 요약 객체 또는 검증 실패 상태 및 실패 사유.

* **실패 조건:** 필수 항목 누락, 항목별 줄 수 초과, 비어 있는 전체 결과, Agent 오류.

* **사용자 안내:** 검증 실패 시 분석 오류 상태로 전달해 F-12의 안내 경로를 사용한다.

* **후속 단계 진행·중단:** 통과한 결과만 F-09에 전달한다. 실패 결과로 투두리스트를 생성하지 않는다.

* **검증 입력·기대값:** 네 항목이 있고 각 항목이 1\~3줄이면 통과한다. 항목 누락 또는 4줄 이상 항목이 있으면 실패 상태가 반환된다.

### F-09 — 요약 기반 투두리스트 생성

* **선행 기능:** F-08 검증된 요약

* **후행 기능:** F-10 투두 필드 검증, 이후 F-11 결과 표시

* **입력 필드·타입·필수 여부:** 검증된 `summary` 객체(필수). 생성 기준 데이터는 요약 결과다.

* **처리:** 요약에서 실행할 수 있는 후속 행동을 찾아 각각 투두 항목으로 분리한다. 원문/요약에 근거가 없는 할 일, 담당자, 기한을 사실처럼 추가하지 않는다. 원문에서 확인되는 근거가 요약에 보존되지 않으면 해당 할 일이 누락될 수 있으므로 요약이 후속 행동 정보를 보존하도록 설계한다.

* **출력 필드·타입:** `todos[]`; 각 항목은 `task` (할 일 설명), `assignee` (담당자), `due_date` (기한), `priority` (우선순위)를 포함한다. 필드의 표시값과 자료형은 확정이 필요하다.

* **실패 조건:** 요약 입력 누락·형식 오류, AI 서비스 실패, 투두 항목 구조 오류.

* **사용자 안내:** 생성 오류는 F-12로 전달한다. 실행 가능한 항목을 찾지 못한 경우 빈 목록과 안내 중 어떤 방식을 쓸지 확인이 필요하다.

* **후속 단계 진행·중단:** 생성 결과는 F-10으로 전달한다. 오류 결과는 성공 목록으로 표시하지 않는다.

* **검증 입력·기대값:** 담당자와 기한이 명시된 요약은 해당 정보를 항목에 연결한다. 할 일이 없는 요약에서는 근거 없는 할 일을 만들지 않는다. 누락된 담당자·기한·우선순위의 표기 규칙은 확인 필요다.

### F-10 — 투두리스트 필드·결과 검증

* **선행 기능:** F-09

* **후행 기능:** 통과 시 F-11, 실패 시 F-12

* **입력 필드·타입·필수 여부:** `todos[]` (필수). 각 항목의 할 일·담당자·기한·우선순위 값.

* **처리:** 각 항목에서 요구된 네 필드가 결과에 표현되는지 확인한다. 값이 원문 요약에 없는 경우 null/‘미정’으로 처리할지, 우선순위 선택값을 어떻게 정할지는 확정이 필요하다.

* **출력 필드·타입:** 검증된 투두리스트 또는 오류 상태. 빈 배열은 별도 정상 결과로 허용할지 확인이 필요하다.

* **실패 조건:** 필수 필드가 구조상 누락되거나 출력 파싱이 불가능함.

* **사용자 안내:** 구조 오류는 분석 오류로 안내한다. 정보가 없는 필드의 표시 방식을 정한 뒤 사용자 안내 문구에 반영한다.

* **후속 단계 진행·중단:** 통과한 목록을 F-11에 전달한다. 실패 시 잘못된 목록을 정상 결과처럼 표시하지 않는다.

* **검증 입력·기대값:** 모든 항목에 할 일·담당자·기한·우선순위 필드가 존재한다. 값이 없는 필드의 기대 표시는 정책 결정 후 확정한다.

### F-11 — 요약 및 투두리스트 결과 표시

* **선행 기능:** F-08 요약 형식 검증 및 F-10 투두리스트 검증

* **후행 기능:** 사용자의 결과 검토; 별도 결과 내보내기 기능은 기존 요구 범위에서 추가 설계

* **입력 필드·타입·필수 여부:** 검증된 요약 객체와 투두 목록(필수).

* **처리:** 요약 네 항목과 투두리스트를 구분해 사용자에게 표시한다. 요약 각 항목의 3줄 제한을 표시 결과에서도 유지한다. 투두리스트는 각 할 일과 담당자·기한·우선순위를 함께 확인할 수 있게 구성한다.

* **출력 필드·타입:** 사용자가 읽을 수 있는 분석 결과 화면. 화면 컴포넌트 및 구체 레이아웃은 프로젝트 구조 단계에서 확정한다.

* **실패 조건:** 한 결과가 표시되지 않거나 다른 결과와 혼합되어 구분되지 않음.

* **사용자 안내:** 일부 결과만 생성된 경우 어떤 부분이 실패했는지 구분하는 정책은 확인 필요다.

* **후속 단계 진행·중단:** 두 결과 모두 검증된 경우 완성 결과를 표시한다. 표시 오류는 성공으로 처리하지 않는다.

* **검증 입력·기대값:** 화면에서 ‘회의 안건·문제점·해결방안·결론’과 ‘투두리스트’ 영역이 서로 구분되고, 투두 항목에 네 필드가 나타난다.

### F-12 — AI 분석 실패 안내

* **선행 기능:** F-07\~F-10 중 AI 호출 또는 결과 검증 실패

* **후행 기능:** 사용자가 안내를 확인하고 재시도하거나 작업을 종료

* **입력 필드·타입·필수 여부:** 실패 단계, 오류 종류, 재시도 가능 여부(내부 오류 정보). 비밀 키·민감 원문·공급자 세부 응답은 사용자 안내에 노출하지 않는다.

* **처리:** 실패 단계와 사용자 조치를 안내한다. 요구사항은 AI 기반 오류 권장안을 원하지만, 분석 서비스 자체가 실패한 경우 권장안을 생성할 별도 모델·규칙은 정해지지 않았으므로 안전한 대체 안내와 AI 권장 방식은 확인 필요다.

* **출력 필드·타입:** 오류 상태, 사용자용 메시지, 권장 조치(문자열). 재시도 한도·지속 실패 시 종료 동작은 미정이다.

* **실패 조건:** 오류 상태가 성공으로 표시됨, 내부 비밀정보가 노출됨, 재시도 반복이 종료되지 않음.

* **사용자 안내:** 실패 단계와 가능한 조치를 이해할 수 있게 안내한다. 반복 실패 시 최종 오류 문구와 지원 절차를 표시하는 기준은 확정이 필요하다.

* **후속 단계 진행·중단:** 분석 결과 생성을 중단하고 불완전한 결과를 완성본으로 표시하지 않는다. 사용자의 재시도 정책이 정해지면 그에 따라 새 분석을 시작한다.

* **검증 입력·기대값:** 요약 Agent 오류, 형식 검증 실패, 투두 Agent 오류에서 각각 오류 상태가 표시되고 성공 결과로 오인되지 않는다. 사용자에게 표시되는 문구에 API 키·스택 추적 등 내부정보가 포함되지 않는다.
